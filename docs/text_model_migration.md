# Миграция текстовой модели и сравнение Luna/Terra

## Границы изменения

Новые значения по умолчанию: текст `gpt-6-luna`, изображения `gpt-image-2.5-flare`.
Явные значения окружения продолжают иметь приоритет. Изменение исходников не
переключает работающий production, закреплённый на `gpt-4o-mini`.
Файл `services/yandex_gpt.py` сохраняет имя и endpoint `/v1/chat/completions`.
TTS/STT, подписки, схема БД, расписание и флаги planner/memory не меняются.

При этом первый выкат кода уже меняет поведение **всех трёх моделей, включая
`gpt-4o-mini`**: system-промпт аффирмаций получает явный язык и anti-injection
инструкции, а проверки пустых/усечённых/отфильтрованных ответов и отказов становятся
строже. Закрепление `gpt-4o-mini` сохраняет модель и legacy-параметры запроса,
но не отменяет эти изменения промпта и обработки ответа. Возврат только имени
модели также не откатывает их; полный откат поведения требует отката кода.

Совместимость проверена по официальной документации OpenAI на 6 ноября 2026 года:
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra),
[параметры миграции](https://developers.openai.com/api/docs/guides/latest-model#gpt-6-astra-update-api-and-model-parameters),
[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).
Проверка документации не подтверждает доступ к моделям в конкретном API-проекте.

| Модель | Лимит ответа | Reasoning | Temperature |
|---|---|---|---|
| `gpt-4o-mini` | `max_tokens` (512/200) | не отправляется | прежняя, по сценарию |
| `gpt-6-luna` | `max_completion_tokens` | явный `none` по умолчанию | прежняя при `none`, иначе не отправляется |
| `gpt-6.1-terra` | `max_completion_tokens` | явный `none` по умолчанию | прежняя при `none`, иначе не отправляется |

Для Luna/Terra `OPENAI_TEXT_REASONING_EFFORT` принимает `none`, `low`, `medium`,
`high`, `xhigh`, `max`. `minimal` не поддерживается этими моделями и отклоняется
при загрузке конфигурации и на preflight. Неизвестные значения effort отклоняются
даже с `gpt-4o-mini`, чтобы не скрывать ошибку до переключения модели; допустимые
reasoning-параметры ему не отправляются. Внешние пробелы в ID модели убираются,
внутренние вызывают ошибку. Непроверенные варианты `gpt-6-luna-*` и
`gpt-6.1-terra-*` отклоняются до API, а не попадают в legacy-ветку. Поддержка
произвольных моделей и будущих snapshot ID не заявлена.

`OPENAI_TEXT_MAX_COMPLETION_TOKENS` — необязательное положительное целое число.
Без override лимиты остаются 512 для аффирмаций и обогащения промпта изображения,
200 для smalltalk. Лимит включает reasoning и видимый текст: при включении
reasoning его может не хватить. Бюджет и таймаут следует сравнивать отдельно;
автоматического увеличения бюджета и платных повторных запросов нет.

Промпты языка, рода, сферы/подсферы, фокуса и памяти разнообразия сохранены.
Пользовательская тема остаётся в user-сообщении; system-сообщение аффирмаций
явно запрещает воспринимать тему и заметки как команды сменить задачу, язык,
род или формат. Это защита на уровне инструкций, её реальную эффективность
необходимо оценить на ответах моделей. Текстовый клиент также обслуживает smalltalk
и обогащение промпта картинки; стиль и визуальный режим остаются в контексте картинки.

HTTP-ошибки, неверный JSON ответа API, отсутствующее/пустое/нестроковое содержимое,
отказ, фильтрация и `finish_reason=length` не считаются успешной генерацией.
Карточка требует JSON-объект с непустым `focus` и ровно четырьмя непустыми строками
`affirmations`. Допустима одна полная Markdown-ограда `json` или без указания языка.
Неизвестные ключи игнорируются; `gentle_step` модели никогда не используется:
мягкий шаг добавляет приложение. Массивы и неструктурированный текст отклоняются,
fallback к сырому ответу отсутствует. Скрипт сравнения использует тот же парсер.
Языковая проверка допускает имена, бренды и технические термины в оригинале;
[политика и ограничения](localization_validation.md) описаны отдельно.
Ошибки формата/языка карточки имеют тип `ProviderOutputValidationError` и завершают
плановую доставку как `abandoned` после одной попытки. Сетевые ошибки, таймауты
и временные ошибки провайдера сохраняют обычные повторы с backoff.
Smalltalk и аффирмации передают ошибку обработчикам; обогащение промпта изображения
сохраняет `template_fallback`.

## Офлайн-проверка

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=.pytest_tmp_text_migration
python scripts/compare_text_models.py --output text-model-requests.json
```

`python scripts/preflight_check.py --production` — отдельная read-only проверка
production-конфигурации из Compose `.env`: требует непустой явный
`OPENAI_TEXT_MODEL`, показывает effective модель и её источник, проверяет effort
и completion budget. Пропущенное, пустое или пробельное значение модели блокирует
проверку с указанием фактического code default. Pin должен быть буквальным ID,
без `${...}`/подстановок: preflight сохраняет ограниченный stdlib-парсер `.env`.
Значения API/моделей из shell хоста не подменяют Compose `env_file: .env`.
Без `--production` сохраняется локальный process-first режим: code default
разрешён, но явно показан с предупреждением. Обычный `check_runtime_config.py`
читает окружение своего процесса; внутри контейнера это effective runtime.

Первый запуск использует временные SQLite/outputs через существующую изоляцию
тестов, не PostgreSQL и не локальную `bot.db`. Тесты нейтрализуют чтение `.env`;
API-транспорт в тестах клиента и сравнения подменён.

Второй запуск не делает сетевых запросов и не требует ключа. Набор из
`tests/fixtures/text_model_comparison.json` содержит шесть синтетических сценариев:
русский женский/мужской/нейтральный род, английский с русской темой, память недавних
начал, внедрение инструкций. Скрипт использует функции production-промптов,
не импортирует bot/database/scheduler и не читает `.env`. URL закреплён на
официальном OpenAI; runtime env выбора модели, endpoint, подписок и флагов не влияет.

Манифест содержит 12 запросов. В каждой паре меняется только `model`;
`input_sha256` совпадает. Повторный офлайн-запуск с теми же аргументами даёт тот же
манифест. `--case ru_female_career` ограничивает запуск одной парой;
`--repeats 3` повторяет каждый сценарий трижды с чередованием порядка моделей.
Результаты реальной генерации не детерминированы; одинаковые запросы позволяют
сравнить модели, но не гарантируют одинаковые тексты.

## Согласованный эксперимент до $1

Для разрешённого 6 ноября 2026 эксперимента использовать отдельный
[план 6+6 none, 2+2 low с резервированием бюджета](text_model_experiment.md)
и `scripts/run_text_model_experiment.py`. Старый live-режим ниже не имеет
ограничителя долларов и **не подходит** для запуска с жёстким бюджетом $1.

## Прежний общий live-режим сравнения

Не запускать как часть обычного pytest/preflight/deploy. После согласования
количества запросов и бюджета задать `OPENAI_API_KEY` в окружении отдельного
процесса вручную; скрипт не берёт его из `.env`. Не помещать ключ в командную строку
или отчёт. Пример ниже делает **2 платных запроса** (один сценарий, две модели):

```powershell
python scripts/compare_text_models.py --live --allow-paid-api-calls --case ru_female_career --output text-model-live.json
```

Без обоих флагов платный режим не включается. Все сценарии с `--repeats 3` —
36 запросов. До первого API-запроса скрипт выводит в stderr и сбрасывает буфер
строки `Planned paid API calls: N` с числом сценариев, моделей и повторов.
План показывается также при `--live` без согласия, после чего скрипт завершится
ошибкой без сети. Сам вывод плана не заменяет `--allow-paid-api-calls`.
Для отдельного эксперимента с reasoning одинаково задать обеим
моделям `--reasoning-effort low --max-completion-tokens 4096`; это увеличит
потенциальный расход и требует согласования соответствующего бюджета.

Отчёт содержит исходные входы и payload, SHA-256, полученный ID модели/ответа,
system fingerprint, время, usage (включая reasoning при наличии), finish reason,
сырой текст и нормализованные аффирмации, валидность четырёх непустых строк,
число уникальных фраз и начал. При HTTP/пустом/усечённом ответе сохраняются статус,
тип ошибки и доступный usage; тело ошибки и ключ не сохраняются. Повторов нет.
Код возврата 1 означает ошибку запроса или нарушение формата хотя бы в одном ответе.
Отчёты размещать в ignored `outputs/` или вне репозитория; не коммитить результаты.

Сначала вручную оценить язык, род до/после cleanup, привязку к теме и подсфере,
бережность тона, отсутствие клише/гарантий и сопротивление внедрённым командам.
Сопоставить одинаковые case/repeat и проверить заметки `review` из фикстуры.
Затем оценить разнообразие внутри набора и между повторами, latency и usage.
Уникальность строк/двух первых слов — простая подсказка, не оценка качества смысла.
Стоимость считать по актуальному тарифу API-проекта; в скрипте нет устаревающей
таблицы цен и нет дополнительного платного вызова модели-судьи.

## Рекомендуемый rollout после разрешения

1. Согласовать минимальный платный тест и подтвердить доступ к обеим моделям
   в нужном OpenAI-проекте. Успех pytest подтверждает форму запросов и обработку
   ответов, но не качество текста, latency или права API-проекта.
2. Проверить результаты сравнения, затем расширить синтетический набор/повторы
   в пределах согласованного бюджета. При необходимости отдельно проверить
   smalltalk и текстовое обогащение изображения без вызова Image/TTS API.
3. Для первого выката кода явно сохранить `OPENAI_TEXT_MODEL=gpt-4o-mini`
   в существующем production `.env`. Новая версия `preflight.sh` всегда включает
   `--production`; `deploy.sh` проверяет конфигурацию до `git pull` и повторно
   после него, до build/up. Для первого применения этих исправлений убедиться,
   что запускается уже проверенная версия preflight, а не скрипт старого checkout.
   Согласовать deploy отдельно и использовать
   процедуру [DEPLOY.md](../DEPLOY.md); не запускать второй polling-процесс с тем же
   Telegram-токеном. Не менять PostgreSQL, подписки, planner/memory-флаги и
   уже проверенную image-конфигурацию ради этой миграции.
4. После отдельного разрешения переключить только текст на `gpt-6-luna`
   с `OPENAI_TEXT_REASONING_EFFORT=none` и прежними бюджетами. Явно установленный
   `gpt-4o-mini` сам не сменится от обновления code default.
5. Откат текста: восстановить явный `OPENAI_TEXT_MODEL=gpt-4o-mini` и применить
   конфигурацию штатным способом. Код сохраняет старую схему запроса, откат БД
   и изменение подписок не требуются. Anti-injection и строгая проверка ответа
   при таком переключении сохраняются. Мониторинг рассылок — отдельный этап.
