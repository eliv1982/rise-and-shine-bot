# Ограниченный эксперимент Luna/Terra — 6 ноября 2026

Разрешён один синтетический эксперимент с бюджетом до $1 USD. Production,
БД, `.env`, подписки и сообщения подписчикам не изменяются. Deploy, commit,
push и платная модель-судья не входят в эксперимент.

| Модель | Effort | Запросов | Максимум токенов ответа |
|---|---|---:|---:|
| gpt-6-luna | none | 6 | 512 |
| gpt-6.1-terra | none | 6 | 512 |
| gpt-6-luna | low | 2 | 4096 |
| gpt-6.1-terra | low | 2 | 4096 |

`none` использует все шесть сценариев `tests/fixtures/text_model_comparison.json`.
Для `low` обе модели получают `ru_memory_diversity` и `ru_untrusted_theme`:
удержание ограничений разнообразия и сопротивление внедрённым инструкциям.
В каждой паре одинаковы входы, инструкции и параметры, кроме модели; совпадает
`input_sha256`. Порядок моделей чередуется. Новые пользовательские данные не нужны.

## Отдельный runner

`scripts/run_text_model_experiment.py` использует production-функции сборки
промптов из существующего сравнения, но отправляет их через **Responses API**.
Это позволяет до генерации получить точный серверный счётчик `/responses/input_tokens`
для того же `model` и `input`. Production-клиент Chat Completions не меняется;
эксперимент сам по себе не доказывает идентичность поведения двух endpoints.

По умолчанию runner только сохраняет детерминированный план без сети:

```powershell
.venv\Scripts\python.exe scripts/run_text_model_experiment.py
```

`--preflight` проверяет GET `/models/{id}` для обеих моделей и подсчитывает
входы всех запросов, **не вызывая генерацию**. Для сети нужен ключ только в
окружении отдельного процесса. Runner никогда не загружает `.env` и не принимает
ключ в аргументах. Внешняя обёртка может передать только `OPENAI_API_KEY`, без
изменения `.env`, вывода значения и загрузки других настроек в окружение runner.

Платный режим требует одновременно `--live --allow-paid-api-calls`.
Не перезапускать платный режим и не создавать другой каталог для обхода claim.
Этот документ фиксирует уже разрешённый одиночный эксперимент, а не разрешение
на дополнительные запуски.

## Ограничение расходов

Проверенные 06.11.2026 тарифы Standard USD за миллион токенов:

| Модель | Input | Cached | Cache write 30m | Output |
|---|---:|---:|---:|---:|
| gpt-6-luna | 0.10 | 0.01 | 0.125 | 0.50 |
| gpt-6.1-terra | 1.00 | 0.05 | 1.25 | 5.00 |

Источники: [тарифы API](https://developers.openai.com/api/docs/pricing),
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra),
[контроль бюджета отдельного запуска](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api).
Цены других дат нужно перепроверять: runner блокирует сетевой запуск в другой день.

1. Только официальный глобальный endpoint, `service_tier=default`, TTL cache 30m,
   `store=false`, без tools, background, streaming, истории, изображений и аудио.
2. Вход ограничен 16384 токенами, ответ — 512/4096. Reasoning уже входит в output
   и не учитывается в цене второй раз. Оба лимита намного ниже документированных
   922000 input / 128000 output и порога long-context 272000.
3. До первой генерации проверяются доступ к моделям, все входы и сумма верхних
   границ. Каждый input считается по самому дорогому входному тарифу, включая
   cache write, каждый output — по полному лимиту. Даже при предельных 16384 input
   на каждом вызове сумма составляет $0.242176.
4. Перед каждой отправкой точный Decimal-резерв сверяется с $1 и сохраняется
   через fsync + atomic replace. Резервы никогда не возвращаются в доступный бюджет,
   включая таймаут, неизвестный usage и HTTP-ошибки. Повторов нет.
5. Ошибка транспорта, неожиданные модель/tier, несоответствие usage/счётчика либо
   незавершённая генерация останавливают запуск. Таймаут может не отменить работу
   на сервере, поэтому резерв остаётся занятым. Эксклюзивный `paid-run.claim`
   запрещает повторный платный запуск в каталоге, в том числе после сбоя.

Ограничение относится к API token usage **этого эксперимента**, не к суммарным
расходам аккаунта или параллельному production. Настройки лимитов проекта не меняются.
Обычный project hard limit не используется как единственная защита: его
[применение может запаздывать](https://developers.openai.com/api/docs/guides/spend-limits).

## Артефакты и оценка

Все отчёты находятся в ignored `outputs/text-model-experiment-2026-11-06/`:

- `plan.json` — 16 запросов, промпты, hashes, тарифы и источники;
- `preflight.json` — доступ к моделям, точные счётчики и верхняя граница;
- `results.json` — checkpoint до и после каждого запроса, исходный текст,
  нормализованные аффирмации, usage, `reasoning_tokens`, latency, статус, стоимость;
- `blind-review.md` и `blind-examples.json` — случайно перемешанные тексты с
  нейтральными ID, синтетическим контекстом и критериями; без моделей и метрик;
- `blind-key.json` — отдельное соответствие ID запросу, модели и effort.
- `metrics.csv`, `summary.json` и `report.md` — метрики каждого запроса,
  агрегаты четырёх групп и итоговый отчёт без дополнительных API-вызовов.

`usage_cost_usd` — расчёт из полного usage, не счёт провайдера. Если API не сообщает
cache-write tokens, точная цена остаётся null; сохраняется
`usage_cost_upper_usd`, резерв не освобождается. Сырой usage хранится целиком.
Слепая версия использует исходный текст до cleanup; упоминания модели в самом
ответе скрываются только в слепой копии. Для оценки production-нормализации
отдельно доступны `affirmations` и `gender_cleanup_changed` в полном отчёте.

Сначала оценить язык, род, тему, бережность, разнообразие и anti-injection по
слепым текстам; затем открыть ключ и сравнить latency и usage. Это малый разведочный
набор, без статистически надёжного ранжирования качества и без повторных генераций.
